# UCZ v19：24位模型与显式 mht4 策略（P11.1）

P11 的原始交付是 `147b778`；其旧说明可用 Git 查看。本页描述 P11.1，**不重新解释旧 v18/v19 文件**。P11 历史门禁与小样本证据仍保留在 `scripts/diag/p11-results/checks/` 原文件名下。

## 最终载荷决定格式，不由全局上限决定

| 实际选中的载荷 | 新编码格式 | 配置头 |
|---|---|---|
| 不需要模型配置 | 与 P10 相同的 v7–v15 | 无 |
| 只需 v18 的低8位语义 | **v18** | **uint8，1 B** |
| 实际使用 CM24 或 mht8=23 | **v19** | **uint16 LE，2 B** |

候选即使曾分配大表，只要最终未选中，也不能增加标志或配置字节。最终子流/组对实际使用的 flags 取并集；成本比较和实际序列化调用同一 `planHeader`。因此整文件 >=8 MiB 也不必然写 v19——只有最终某个组实际需要 24/23 才需要它。

无配置时仍保留 v7–v15，而不是强行加上 v18 头；这是保持 P10 字节身份的一部分。

```
v18: 55 43 5a 12 <flags:u8> <rawLen:varint> ...
v19: 55 43 5a 13 <flags-low:u8> <flags-high:u8> <rawLen:varint> ...
```

上述 `12/13` 为十六进制版本号。组字典的 `r | 0x8000` 仍表示 v15 内核，`0x4000` 仍表示 WORD-PRE；合法行宽8192的 `0x2000` 不被占用。

## 配置位与兼容分支

| 位 | 含义 |
|---|---|
| `0x001` | 全局 text a2 关闭 |
| `0x002` | 实际 CM 宽度22 |
| `0x004` | 实际 CM 宽度23 |
| `0x008` | 实际匹配表宽度21 |
| `0x010` | 实际匹配表宽度22 |
| `0x020` | res a2 关闭 |
| `0x040` | 仅 WORD-PRE text a2 关闭 |
| `0x080` | 历史诊断 unscoped 模式；默认不设置 |
| `0x100` | **实际 CM 宽度24**；仅 v19 |
| `0x200` | **实际 mht8 宽度23**；仅 v19 |
| `0x400` | **P11.1：size-scoped mht4 固定上限20**；仅 v19，且必须同时有 `0x100` 或 `0x200` |

v18 的8位均已占用，P11.1 **没有占用或改写任何 v18 位**。`0x400` 是 v19 原先空闲的扩展位。

- **v18**：一个配置字节、CM最大23；size-scoped mht4 固定20。
- **旧 v19（无 `0x400`）**：仍按 P11 的 mht4=20/21/22/22 分档解码，包括只携带低8位的旧 v19 文件。
- **新 v19（有 `0x400`）**：CM/mht8 分档不变，mht4 各档固定20。
- v17 保留旧位编号与旧子流长度策略；更早版本不变。

例：9上下文 bin/v15 的超大组，旧 P11 为 `[24,22,23]` / flags `0x310`；P11.1 为 `[24,20,23]` / flags `0x700`。不能简单改旧 v19 的默认 mht4，否则旧流会被错误解码。

v19 允许掩码为 `0x7ff`。孤立 `0x400`、未知位、配置截断、未知版本，以及 unscoped 与23/24位CM或22/23位匹配表组合均拒绝。旧诊断 unscoped 的 CM21/22、match20/21 解释保持不变；它不是默认生产分档。

旧 P11 解码器不识别新 `0x400`，会明确拒绝新高档文件，需升级后读取；新解码器兼容旧 P11 文件。P10 可读兼容的 v18 低档文件，不支持 v19 高档格式。

## 默认生产分档

`modelTuning = { maxTableBits: 24, matchTableBits: 23, largeOnly: true }`。

| 最终组/独立块的原始大小 | CM上限 | mht4上限 | mht8上限 |
|---|---:|---:|---:|
| `<512 KiB` | 21 | **20** | 20 |
| `[512 KiB, 4 MiB)` | 22 | **20** | 21 |
| `[4 MiB, 8 MiB)` | 23 | **20** | 22 |
| `>=8 MiB` | 24 | **20** | 23 |

小流仍按长度自适应分配，表中是上限。空流不借用父级大小。普通组按组；TG最终CM通道按完整转置组；WORD-PRE按变换前原始组；SUB按独立且最多8 MiB的块；二维转置按实际区域。原始不足8 MiB的组不会因变换膨胀误升24位。分档不是按文件名。

## 小文件的 P10 选择策略

P11 不仅更改 mht4/头，还给整个 `chooseSpec` 加了探针上限并把孤儿上限24改为64。为了恢复默认小文件的 P10 字节路径，P11.1 同时规定：

- **整输入 <8 MiB**：`chooseSpec` 恢复 P10 的 512 KiB复核/完整候选比较；不强压这些比较到21位。孤儿候选最多24个不同规则组。
- **整输入 >=8 MiB**：保留 P11 `chooseSpec` 的 CM<=21、mht4/mht8<=20 探针上限，孤儿最多64组。
- 主线程与 worker 使用**同一个整输入长度**，不能把大文件里的小区域误判成小文件。
- TG布局、SUB模式、二维列、WORD-PRE前缀、同族样本、宽行/锚点小窗仍用同步有界探针。其默认原始窗口本已小于512 KiB，与 P10 的有效分档相同。默认 <8 MiB 宏为直接完整比较，不走大文件的1 MiB采样筛选。
- 小文件例外是遵从本轮 P10 字节身份要求，不再声称“所有 chooseSpec 复核都 <=21”。

孤儿条件 `<2 MiB AND <20%`、排除FILL、一次批次、真实重新编码、完整容器严格择优均保留。P11 精确 base/cost 复用与 candidate-only worker 不改变选择规则。

## 内存边界

9上下文24位表体为 **576 MiB**。新 mht4=20 为4 MiB，mht8=23 为32 MiB，总表体 **612 MiB**；旧 P11 为624 MiB。即 mht4 从22降20，每个这样的 live model 少 **12 MiB**，不是24 MiB；从21降20则少4 MiB。不能直接当成实测 worker RSS 降幅。

默认仍按 **1024 MiB/worker + 1024 MiB余量**估算并发；显式 `UCZ_THREADS` 不被暗改。输入、变换、候选缓存与GC另占内存，这不是RSS硬上限。

## 验证边界

P11.1 新增实际输入最大48 KiB：固定 P10 旧源码的6份完整容器逐字节比较、两档128 B raw-CM历史对照、旧 P11 v19 raw-CM解码、真实生产 v18 头写入器及4批真实worker。边界/原始组大小使用虚拟标量，不冒充大输入压缩率测量。另按请求执行既有完整 codec 套件。

参见 [P11.1交付说明](P11_1_HANDOFF.md) 和 `scripts/diag/p11-results/checks/small-smoke-p11-1.json`。xml/reymont/ooffice 目标与所有小于8 MiB语料的实际字节身份仍需用户本机全量验证。
