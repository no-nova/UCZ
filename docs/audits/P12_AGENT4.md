# P12 审计单元 4：WORD-PRE、空格/标点耦合与词表有效容量

日期：2026-11-07。生产参考仍为 `a3b6c3d`；xml/dickens/reymont/nci/samba/webster 用户本地基线合计 **14,814,311 B**。本轮没有修改生产编码源码、默认格式或worker。本环境无Subagent调度接口，此处为第四独立审计单元。

## 1. 结果摘要与证据等级

- **47次独立实验，原始输入全部256KiB，全部往返通过，最长11,920ms。** 每次进程17.5s预算，另有19s外部SIGKILL保护。未运行任何完整语料压缩或完整codec套件。
- 其中 **33次由当前生产 `planHeader` 组装有效UCZ，并由未修改的生产 `decompress` 恢复原文SHA**；14次是研究v2封装，仅直接CM+库级v2逆变换往返，不冒称兼容UCZ。
- raw text用当前a2on；WORD-PRE用当前词元模式/a2off。不是拿旧a2配置制造收益。
- **v1早已能含空格、标点/标记子串；v2尾随单空格与双层词表也已经存在。** 不把它们称为新发明。但v2没有接入生产codec的正反路径，旧注释与真实常量也不一致。
- 单纯扩大词表、吞空格、独立处理更多词元并未稳定胜过现有较优方案。更小且有证据的方向是：**先按实际非重叠命中去掉无用词条，再复用原v1单字节格式**。两个XML位置、两个nci位置，完整单组UCZ合计少 **1,968 B**；webster则回退1,147B，必须保留严格按实际成本的候选护栏。

证据：`scripts/diag/p12/agent4.ts`、`p12-results/agent4/*.json` 和 `summary.json`；每份含输入/生产源码/诊断工具SHA、字节数、词条实际命中、时间和往返记录。后加nci-late固定为75%位置，并在实验前追加manifest；没有按收益搜索偏移。

## 2. 真正的生产路径与未接通部分

### v1

`wordpre.ts:21–230`：最多120词条；候选为长度3..12的高频子串，宽字符集已包含字母/数字、空格、`.`、`,`、`<`、`>`、`/`、`_`。净节约评分 `c*(len−1)−(len+1)>0`，避开相互包含的已选词条，字典按长度编号，正文最长匹配。

所以v1并不是“词后空格从未合并”。例如dickens中窗已有16,012次尾空格词元命中。它也不是完整自然语言分词器；字母级词模型与预编码子串不是同一层。

### v2已有实现，但不是已启用的兼容模式

`wordpre.ts:333–564` 的真实布局是：

- **127个**单字节词条：0x80..0xfe；**256个**双字节词条：0xff+一个索引字节。
- 0x7f转义原始>=0x7f字节；候选池合并v1子串与完整词/尾随单空格。
- 旧注释还写64+2048、0xc0..0xc7，以及“codec用长度最高位区别”，均不能作为当前事实。
- `codec.ts` 实际只导入v1，`wordPreTry`只调 `wordPreFwdSampled`；解码只调 `dictHeaderLen` / `wordPreInv`。**库级 `wordPreInv2` / `wordPreInvMode` 存在，不等于容器解码已经支持v2。** 本次复读据此纠正早期“v2解码已接通”的初读假设。

v2的实验封装明确为 `[mode=2:1B][tokenStreamLength:u32][CM(dict||body)]`。这是诊断私有封装，不借用合法的r=8192对应0x2000，也不静默复用v18占满的flags。

### 当前候选资格与预筛

`codec.ts:2032–2107,2159–2188`：

1. 只有 **spec.id=TEXT_V3(23)** 的分组调用WORD-PRE，不是所有含ASCII的BIN/BCJ/DELTA分组都自动使用。
2. 原始组至少32KiB；256KiB固定采样建v1词表；body/raw必须<=0.85。
3. 使用最多192KiB前缀，同词表比较raw text-v15与token-v15；后者须小于前者的0.99。
4. 通过后才编码**词典头+完整词元正文**，加4B长度前缀；外层与base/v15按真实序列化头严格择优。

函数旧注释的“64KB/55%”不是当前门槛。前缀wpProbe不含词典，因而只是筛选而不是收益证明；最终完整成本门仍不可省。

## 3. 六类文本：缩短词元流不等于缩小最终CM

下面raw/v1两列均是**真实单TEXT3组完整UCZ**，不是只比裸正文。v2列仅是上述研究封装，尚不含生产外层/新增模式成本，不能直接当同口径完整容器。

|256KiB切片|raw text完整UCZ B|强制v1完整UCZ B|v1相对raw|v2研究封装B*|v1正文/raw|v2正文/raw|
|---|---:|---:|---:|---:|---:|---:|
|xml-stats|12,942|12,135|−6.236%|12,863|40.38%|39.29%|
|nci-mid|13,795|13,854|+0.428%|14,074|40.04%|32.32%|
|samba-c|32,691|33,537|+2.588%|34,493|73.28%|71.26%|
|webster-mid|57,284|60,088|+4.895%|59,307|68.68%|72.07%|
|dickens-mid|70,389|77,386|+9.940%|81,340|68.31%|65.73%|
|reymont-mid|48,387|49,203|+1.686%|50,565|70.07%|70.38%|

`*` v2研究封装已经含5B前缀、编码后的词典成本，但**没有有效UCZ外层**。即使暂时忽略缺失外层，它在本表也没有胜过raw/v1中的较优者。所有比较都保留这个口径边界。

samba-c从真实C源文件开始，但该成员只有219,702B，其后为紧邻tar数据；不是声称整256KiB都为C，更不能从此断言整份samba没有有利的WORD-PRE组。

### 调用真实生产预筛函数，而不是猜测原因

在同一个固定TEXT3候选分组上执行 `groupV15CandidatesSync`：

|切片|raw v15 payload|实际返回的WP候选payload|结论|
|---|---:|---:|---|
|xml-stats|12,923|12,115|v1已经在实际路径上受益；完整UCZ12,135B|
|nci-mid|13,776|null|当前v1被预筛挡下；强制整组v1也并未胜出|
|samba-c|32,671|null|当前v1被预筛挡下；强制整组v1也回退|

这是**真实函数在短切片上的调用结果**；不是整文件最终分组复测。原用户日志没有全部TEXT3/BIN组目录，不能把“该切片预筛失败”扩大成“整个samba因为某一条件永不尝试”。

## 4. 词+一个空格、词+标点的定量对照

另作不改变v1线格式的受控词表实验：统一120个单字节槽，每个词族最多一个条目；比较整词、整词或尾随单空格、再允许单个标点 `.,;:)>`。选择仍按明确的原字节净节约评分，不扫频率/学习率参数。候选集变化会改变入选词，不把它误称固定词表的单因素证明。

|切片/词表|词元正文B|最终完整UCZ B|尾空格命中|尾标点命中|
|---|---:|---:|---:|---:|
|webster：整词|216,819|58,158|0|0|
|webster：整词/单空格|217,499|59,212|7,260|0|
|webster：再加标点|209,801|59,179|7,187|8,346|
|dickens：整词|194,545|70,269|0|0|
|dickens：整词/单空格|190,185|73,192|19,176|0|
|dickens：再加标点|189,828|73,135|19,128|462|

- dickens吞空格使正文少4,360B，却使完整UCZ **多2,923B**；后续标点再少357B正文，仅少57B UCZ，仍败给raw。不能把消失的空格字节直接算为压缩节约。
- webster加标点使正文相对words-space少7,698B，UCZ仅少33B，仍比raw大1,895B。
- dickens整词单窗比raw少120B（0.170%），幅度小，且webster同策略比raw大874B；不据此新增默认全局分词规则。

已有CM能低成本预测空白和常见字母序列。提前改写这些序列会改变词/字符上下文，最终影响必须以CM码长衡量。

## 5. 有效容量、频次阈值与webster覆盖

### 5.1 383个槽不等于383个被使用的词

|切片|v1已选/未用|v2已选/未用|v1原文被词元覆盖|v2原文被词元覆盖|
|---|---:|---:|---:|---:|
|xml-stats|120 / 66|383 / 330|68.61%|72.84%|
|nci-mid|120 / 37|383 / 276|69.99%|79.49%|
|samba-c|120 / 41|383 / 200|33.44%|36.48%|
|webster-mid|120 / 39|383 / 294|39.54%|36.42%|
|dickens-mid|120 / 0|383 / 39|45.47%|51.92%|
|reymont-mid|120 / 15|383 / 236|42.05%|46.71%|

未用按**真实最长匹配后正文**统计，不是低频猜测。v2合并的两路统计会对同一完整词重复计数；多个相互覆盖的子串都能拿到高评分，但匹配后多数不使用。容量不是唯一瓶颈。

webster这窗识别7,361个不同完整词候选；整词120槽覆盖原字节26.62%，而v2扩大后仍有294项未用，原始词典头从v1的1,008B增至3,454B。不能用“词典太小”解释所有缺口，或只报告理论Top-K覆盖而跳过实际匹配。

### 5.2 阈值是原字节盈亏，不是最终CM盈亏

- v1: `c*(L−1)>L+1`。L=3至少3次；L>=4通常至少2次。
- v2双字节: `c*(L−2)>L+1`。L=3至少5次，L=4/5至少3次，L>=6通常至少2次；但这里的c含重叠候选/两路合流，不保证是实际可命中次数。
- 词典编号注释写“按频次”，实际v2单/双档分别按g1/g2的**长度加权节约分**排序，不是纯命中次数。

明确的容量消融（保留v2的同一单字节表，删掉整个双字节层）：

|切片|v2默认正文B / 研究封装B|v2仅127单字节正文B / 研究封装B|
|---|---:|---:|
|webster-mid|188,932 / 59,307|197,356 / **57,823**|
|nci-mid|84,728 / 14,074|86,059 / **13,241**|

更长正文却更小CM，证伪“加词条越多越好”。这不是建议把某个容量硬调成最优值；本轮没有做参数网格搜索。

## 6. 双字节词元边界：已有CM只理解v1式高位字节

`coder.ts:1095–1112` 的wordTokens逻辑把每个>=128字节视为一个完整词。v2的0xff lead会先被当成词，索引字节若是ASCII字母又参与字符词哈希，若>=128再被当另一词；并没有把一个双字节词元原子化。

只在诊断副本增加lead/escape状态，将lead+index合为一次词身份推进，双方均从已读字节推导、不依赖未来原文；词典头也仍流经同一CM，未声称是完美的语义词模型。相同v2词典/相同正文，只变边界处理：

|切片|原v2研究封装B|原子词元变体B|ΔB|
|---|---:|---:|---:|
|xml-stats|12,863|12,503|−360|
|nci-mid|14,074|14,006|−68|
|webster-mid|59,307|59,448|+141|

这个调用/建模差异确实存在，但不是普遍正收益，更没有胜过上述较优现有方案。若将来上线必须显式区分CM语义和v2格式；本轮不改v15旧流解释。

## 7. 更低风险的候选：实际使用计数、复用v1线格式

### 简单移除原v1中未用词条

同样的原文字节覆盖、正文长度不变，但词典与编号变化：xml-stats完整UCZ **12,135→11,873（−262B）**，nci-mid **13,854→13,735（−119B）**，webster **60,088→59,836（−252B）**。webster仍比raw差2,552B，不能因为“比旧WP更好”就采纳。

### 更大候选池 → 非重叠实际命中 → 最多120个v1槽

`pool-repack-v1`：只复用现有v2建表得到的候选词；先按真实正文解析命中，删除未用条目、按实际命中排序，最多保留120项，再用**既有v1词典/词码/4B长度前缀**编码。不新增码位、ID、flags或解码逻辑。实际完整容器都由未修改生产decoder验证。

|独立256KiB位置|raw完整UCZ|原v1完整UCZ|本轮两者较优|新候选完整UCZ|ΔB / %|
|---|---:|---:|---:|---:|---:|
|xml-stats|12,942|12,135|12,135|11,569|**−566 / −4.664%**|
|xml-mid（另一XML成员）|6,066|5,576|5,576|4,930|**−646 / −11.585%**|
|nci-mid|13,795|13,854|13,795|13,500|**−295 / −2.138%**|
|nci-late（固定75%位置）|13,395|13,189|13,189|12,728|**−461 / −3.495%**|
|webster-mid，负对照|57,284|60,088|57,284|58,431|**+1,147 / +2.002%**|

正向四位置共 **1,968B** 的**完整单组容器**节约，不把webster的回退用其它文件抵消。可作为保留当前结果的独立候选；不能默认替换全部词表。XML/nci组长度、词表跨多成员的泛化、前缀门槛如何筛选这个新候选、额外两遍统计的全文件开销都尚未验证。

原v2也做了相同命中重排作机制对照：xml/nci/webster研究封装分别11,550/13,481/58,412B；这些词表实际使用都<=120项，根本不需要v2双字节语法即可兑现大部分局部效果。不要为局部容量问题先引入新格式。

## 8. 本轮判断

1. **保留研究候选：有效词条重排并复用v1。** 四位置完整容器同向，复杂度低于新v2；负对照证明严格成本护栏不可撤销。未证明整文件零回退。
2. **不建议默认：**只增词表容量、全局吞空格/标点、直接接v2或更改wordTokens语义。v2代码存在但需正反路径及版本设计，不能靠调用一个函数就宣称上线。
3. **不把历史或注释当测量：**当前samba切片实际预筛返回null，XML切片已有收益；全文件最终WP组目录仍需原容器或原运行JSON，不能从汇总大小推断。

复现例：`P12_RUN_TAG=replay-agent4 timeout --signal=KILL 19s node scripts/diag/p12/run.mjs agent4 xml-mid pool-repack-v1`。收据拒绝覆盖；原始语料与切片均ignored，只有小型工具/JSON/报告入Git。
