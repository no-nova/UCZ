### C2：嵌入式 worker 与源码不一致（起点已证实；现已重建并通过完整 worker 测试）

## 3. 不应继续传播的推论

这些修正不否定整份报告，但不能作为 P9 验收依据：

1. **R3 §2.2 的熵表不可能同时成立。** 若 `H(cls)=2.21`、`H(ASCII二分)=0.47`，则 `H(cls|ASCII) >= 2.21−0.47 = 1.74 bit`，不能是表内 0.02 bit。二分类准确率也不能证明其余四个地形标签被解释。
2. **“差分后匹配归零”混淆了变换和 profile。** 代码中 `useMatch` 仅 text/bin 为真，res/res2d 根本没启用匹配模型。不能由 res 桶=0 单独证明差分毁掉所有重复。R2 同节称 mr 残差仍有匹配，也与该门控及其表中 0% 不一致。
3. **R3 分组表的字节减法错误。** `3,272,858 − 3,230,084 = 42,774 B`，不是 42,304 B。不能把后者当成精确验收目标。
4. **R3 “nci STORE 被 consolidateOrphans 并回”与旧代码相冲突。** P7 的过滤器明确排除 STORE。该段不能用于解释不同入口的容器差值。
5. **“零命中 = 零体积风险”不成立。** R3 死 ID 清单里 DELTA、BCJ、GRAD/GRAD_V2 在自己的表中也有胜出；R1 所谓零命中只覆盖它的样本。删除候选还可能改变后续分组。
6. **“小窗口严格择优 = 全文件单调不劣”不成立。** 旧 orphan/macro 都含热前缀或切片估算；新的宏门已加入最终容器复核（§8），orphan 不在这次保证范围内。
7. **预算/增益不能跨口径外推。** R1 的 samba 单组差 143,316 B 不能直接归因给提高 sample floor；R2 的整片 TG 差不能直接归因给逐段候选；不同 offset/profile/kernel/分组不能混成一张累计收益表。
8. **表宽与所谓“内部上界”。** 增加 1/2 bit 是槽数 ×2/×4，不是 R2 文中的 ×4/×16。有限候选、短片段、特定熵估计不足以证明模型族或整个问题“到顶”。
