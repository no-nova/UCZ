# P12 审计单元 2：sao 列结构与 mr / x-ray 16bit 残差

日期：2026-11-07。生产源码仍为 `a3b6c3d`；12 文件新基线 41,814,147 B；本组三文件用户本地大小之和 **9,450,134 B**。没有重测完整文件，没有生产源码/默认格式改动。本环境无真实 Subagent 接口，此处为第二独立审计工作单元。

## 1. 实验边界与结论

- 31个独立短进程：**28个压缩实验全部 roundtrip PASS**，另3个只作熵/行宽统计；原始输入64–256KiB，单次最慢 **10,050ms**。runner的17.5s子进程预算外，再由 `timeout --signal=KILL 19s` 包裹整个构建/执行。没有全codec测试或长语料编码。
- `scripts/diag/p12/agent2.ts`、`p12-results/agent2/*.json` 和 `summary.json` 可复现；每次有源码/工具/输入SHA。三个 stats 收据中的通用 `roundtrip:true` 只是探针占位，**未做编码，不计为压缩往返证据**。
- **最有价值的机制差异：现有 WIDE_GRAD(s=2) 是逐字节 MED，不是真16bit像素 MED。** 对完整16bit值做MED再输出LE交织残差，四个独立位置相对本轮已测的最佳现有候选共少 **12,346 B**。
- **不建议拆开MSB/LSB。** 高字节边际熵低不等于可独立编码：符号/进位与低字节强相关，实压拆流均回退。
- sao现有TG3**已经做同列跨记录Delta及相邻列动态规划**；单纯逐字节自适应Delta+重规划没有收益。保留进/借位的32bit字段Delta+原TG3重规划，在两个位置净少523B、4,102B，但泛化尚未证明。

## 2. 先纠正ID及实现归属

`src/lib/codec.ts:16`：D16=**8**；BCJ_V3=**25**；GRAD_V3=**26**；SUB_TRANSPOSE_V3=28；SUB_ANCHOR_V3=29；TG3=30；WIDE_GRAD=31。**不存在 SUB_D16_V3 / SUB_WIDE_GRAD_V3 这两个ID。** 不能把25/26的大小归因成所谓SUB残差瓶颈。

- `transforms.ts:d16Fwd`：16bit LE一/二阶差分，结果仍为低/高字节交织；CM的res profile用s=2划分相位，既有相位独立的条件，又保留相邻字节信息。
- `codec.ts:780–786,864–880`：WIDE_GRAD(s=1)实际直接走d16Fwd(1,1)+res(s=2)，其r不参与预测；s=2才走 `medFwd(data,2,r)`，后者在 **8bit字节值** 上做MED。
- GRAD_V3同样逐字节MED；res2d默认已排除a2。WIDE/D16另按ID抑制a2；因而本轮同s/r的GRAD_V3与WIDE式byte-med输出完全相同，不是“新增关闭a2”的收益。

## 3. sao：28通道熵、已有分组及可逆字段差分

固定中窗262,136B=9,362条28B记录；全文件来源与偏移见 `p12-results/slices.json`。记录步长28是已有候选几何，不凭空推断字段语义。前两个8B以LE binary64解释，开头分别约0.4569965、−0.1134751，第一字段相邻记录递增；这支持数值字段假设，但本轮没有外部格式规范来给它们冠以精确天文坐标名称。

### 3.2 现有TG3不是固定四桶

`codec.ts:605–760`：最大段中央16,000B、记录对齐；跨度 `[1,2,3,4,6,8,12,16,24,32,64]`；正/逆序；对STORE/FILL/RLE/O0/BIN/DELTA实际编码；动态规划**相邻列**总成本，含span/mode/varint长度头。Delta按group span预测上一记录同列。计划以v13成本搜索，再用请求的v15内核编码；最终膨胀回退STORE。a2与辅Mixer在TG3 v15内部对称抑制。

中窗真实TG3 payload（139,892B，已经含子组头）布局：

|列范围|模式|payload B|组头B|
|---|---|---:|---:|
|0|STORE|9,362|4|
|1–4|STORE|37,448|5|
|5–7|DELTA|2,363|4|
|8–13|STORE|56,172|5|

因此重新提出“把5–7列Delta、低熵列聚类”大部分是在重复已有机制。v13计划/v15最终编码的目标差异是可审查点，但**本轮未量化其单独收益**，不宣称更改计划内核能省多少。

### 3.3 同一输入、同一TG3规划器的两种前处理Oracle

- `tg-adaptive`：在切片前1/4训练，各列H0决定原始或同列byte-Delta；之后对转换后的完整切片重新调用**现有TG3**规划/编码。计4B列掩码。
- `tg-delta32`：同样前1/4训练，将28B视为7个LE32 bit-pattern字段，按相邻记录作模2^32差，保留字段内借位，按四列H0之和选原始/差分，然后现有TG3重规划。计1B字段掩码。**不是有舍入误差的浮点数值减法**；逆变换精确恢复原始位模式。
- 掩码字节是明确的诊断侧信息成本；往返使用记录的掩码。没有分配生产ID，也没有假装输出是兼容UCZ容器。外层版本/模式/计划目录仍未计价。

|---|---:|---:|---:|---:|---:|
|sao-mid，262,136B|139,892|139,946|+54 / +0.039%|139,369|**−523 / −0.374%**|

## 4. mr/x-ray：MSB/LSB的边际熵与实压相反

固定256KiB中窗，LE16一阶残差的低/高字节边际熵：

|切片|低字节H0|高字节H0|检测到的r字节|
|---|---:|---:|---:|
|mr-mid|4.8151|0.9254|1,024|
|x-ray-mid|7.3105|1.0040|3,800|

全0/0xff高字节多，表示小正/负残差；低字节提供符号/借位相关信息。交织res(s=2)可以用这种条件关系；两张独立CM无法跨流看到低字节。实压（v15，保持现有row a2策略）：

|切片|D16交织B|D16分低高两CM，含4B分流头|相对D16 ΔB / %|真16bit MED交织B|真16bit MED拆流，含4B|
|---|---:|---:|---:|---:|---:|
|mr-mid|59,386|71,436|+12,050 / +20.291%|52,177|61,460|
|x-ray-mid|119,784|135,502|+15,718 / +13.122%|117,359|132,761|

mr把低高字节串联进**一个共享**CM（非两个模型）也为71,453B（含1B模式），没有救回损失。拆流的两个原始长度由总长度推导，计1B模式+第一个压缩流长度varint；不含新UCZ ID的额外成本。不能把MSB低熵当作净收益上界直接加到总成绩上。

## 5. 真16bit二维MED：同一结构性差异，四位置验证

新诊断变换在LE16完整采样值上，按左/上/左上做MED，差值取模65536，再以低/高交织输出；CM仍用既有res2d(s=2,r)。与byte-med比较时，CM/行宽/流数相同，不新增学习率或启发式桶。切片边缘以0作缺失预测值，逆变换对称。

`detectWide16Lag` 在每个256KiB内自行以三个64KiB窗口确认宽度，两处mr均1024，两处x-ray均3800。没有把整文件拿来搜索，也没有枚举一串手调宽度。原实现**已经能找到正确候选宽度**；主要差异在预测器的数值域，而非“加大stride上限”。

|256KiB位置|D16现有B|逐字节MED现有B（GRAD3实路复核）|本轮现有较优B|真16bit MED B|相对较优ΔB / %|
|---|---:|---:|---:|---:|---:|
|mr-mid|59,386|55,830|55,830|52,177|**−3,653 / −6.543%**|
|mr-late|68,244|62,997|62,997|58,261|**−4,736 / −7.518%**|

“本轮现有较优”只指表内已测ID8/26/31对应内核，不是完整adaptive chooser胜者，更不是用户整文件的最终组。四次独立实验的payload节约和 **12.346kB**；新模式必须有可识别的变换ID/版本和完整容器成本门禁。本轮不冒用ID26或31改变历史解码。

## 6. MAX_SUB_CHUNK、transpose2d、sub-peel是否真瓶颈

- `codec.ts:391–417` 的8MiB cap只在SUB_TRANSPOSE/SUB_ANCHOR族打包同源子通道时使用；D16、GRAD3、WIDE、TG3不是每到8MiB就重置CM。普通terrain变换每region重置，**CM按整个同规则组共享**。因此仅凭mr/x-ray大小超过8MiB就主张扩大MAX_SUB_CHUNK，归因不成立。
- `sub-peel.ts` 已逐列实选5种模式，并比较独立列流与按模式聚合共享流（含模式表、长度头）。不是简单固定熵分桶。它仍有局部采样/模态错配风险，但未证明是这两个图像的最终路径。
- `transpose2d.ts` 逆序列、每列4096B小窗决定原样剥离、剩余列用几何stride=rowCount的bin编码，每region独立。它不等价于16bit图像MED，也没有承诺跨region共享二维模型。
- WIDE局部候选会被默认dropZeroHitIds剔除；另有整输入碎片过多时的widePick通道，要求至少256KiB且多窗口真实编码胜出。这里没有运行整输入分段/归组，不能断言某个本地文件未入池的唯一原因。
- **本轮没有8MiB以上编码、扩大cap或大组RSS测量。** 不能据此给cap扩容排序或吞吐承诺；短窗结果支持先改正确的数值域，而不是扩大资源限制。

## 7. 下一步优先级与回退风险

1. **真16bit MED：高优先研究候选。** 四位置同向、低实现复杂度；需要对齐/端序/有符号或非像素输入的防误用，以及新格式版本、worker/双内核一致性。逐完整文件严格比当前基线更小才可替换。
2. **sao LE32字段Delta+已有DP：中优先候选。** 两位置收益差异大，假设字段布局的风险高；训练/保留窗口应分开，掩码、头与整组成本不能省略。byte自适应单独不推荐。
3. **MSB/LSB独立拆流与MAX_SUB_CHUNK扩容：本轮不支持。** 前者实测负收益，后者不是已证实的路径瓶颈。

复现例：`P12_RUN_TAG=replay-agent2 timeout --signal=KILL 19s node scripts/diag/p12/run.mjs agent2 mr-mid med16`。原始记录不可覆盖；工具快照与源版本都在收据中。生产代码仍不变，三文件本地新上限仍为3,747,789 / 2,039,355 / 3,662,990B。
