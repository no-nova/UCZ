## 交付结论

四份独立审计报告、短切片Oracle、原始收据及本汇总均已落盘。**本轮没有改变生产源码、默认格式或比特流。** 当前生产算法参考仍是 `a3b6c3dd3b69f0ac65b06482313de880a2322a4f`，严格基线仍为 **41,814,147 B**，没有声称P12已把全语料压到一个新的总大小。

最值得继续研究的实证方向是：

1. **真16bit MED**，不是把高低字节拆成独立CM。
2. **核查已有TG3对同构代码/结构体的规划覆盖**，不是重新发明分组转置。
3. **跨记录保留借位的字段Delta**，而不是在sao上重复已有byte-Delta。
4. **按实际命中整理词表、复用v1格式**，而不是直接启用未接通的WORD-PRE v2。
5. **纠正默认关闭恢复路径的距离错位，再隔离验证启用**，而不是增加已有的mht4确认。

**重要缺口：Mozilla P11.1那次实际最终组目录仍未知。** 原容器/完整分组JSON未提供，本轮没有违反短测限制重编码整文件；已交付只读目录工具。四份报告完成不等于这个缺口已经补证。

## 2. Top 5：局部实测、条件推算、复杂度与风险

**单位：1kB=1000B。** 排序综合潜在收益、机制/证据强度、复杂度和回退风险，不把一次冷切片的最大百分比当作优先级。

“条件推算”只把两个位置的 **节约B/输入B** 套到明确覆盖范围，区间端点来自两位置的最小/最大比率。它**不是全文件测量、统计置信区间、理论上界或收益承诺**。模型冷热、表宽、最终组构成、外层成本和适用覆盖率都可能不同。完整算式及逐case来源在 `scripts/diag/p12-results/top5.json`。

|排序 / 优先级|方向|局部实测节约|条件算术推算kB及覆盖假设|复杂度|主要回退/归因风险|

## 3. 哪些原假设被源码和实测否定

|审计点|核实结果|本轮证据|

|“mht4盲信哈希”|已有最多32字节逐字节确认；mht8最多64字节|新增显式4字节预检三窗**0B且SHA一致**；minLen提高三窗均退|

## 4. 关键未验证事项与下一阶段门禁

### 尚缺的实际数据

1. **Mozilla a3那次最终group目录/成员offset/各payload。** 历史P8组数、切片analyze分段数、用户最终大小都不足以推出它。
2. mr/x-ray整文件最终规则及region边界、所有候选的完整容器对照。
3. 新预测/恢复在warm大组、CM22/23/24、mht8大表、原始分段重置、dual/worker下的行为。
4. 新词表在跨多个文本成员、整组采样词典上的收益与额外统计开销。
5. 本轮没有新全语料吞吐/RSS结果；短进程时间只证明限时，不能作为性能排名。

无需重压缩的Mozilla目录提取：

```sh
node scripts/diag/p12/inspect-container.mjs /path/to/existing/mozilla.ucz --baseline mozilla > mozilla-p111-groups.json
```

工具只读取已有容器，不编码、不解码。给出真正的wire group/members/ranges，保留r8192；基线大小匹配不是原文SHA/生成commit证明。目录中的orphan大小资格不是合并收益。

### 若后续获准实现，必须保留的门

- **本轮不实现默认算法变化。** 后续每次只隔离一个机制，先按既有格式规则设计可区分的语义；不改旧25/26含义，不挪用0x2000，不静默复用v18占用位。
- 原始结果必须作为兜底缓存保留；只有完整候选容器**严格更小**才采用，相等/更大保留原结果。
- 逐文件检查全部12个bestUcz，**任一文件1B回退都不能用其它文件的收益抵消**。
- 兼容旧版本、编解码/dual/worker一致性、内存和时间需另行验证；本轮短测不替代这些门。
- TG规划方向先取得真实最终目录，区分“已有方案已兑现”与“候选未进池/聚合不足”，不先全局打开启发式。
