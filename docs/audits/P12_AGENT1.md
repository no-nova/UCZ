# P12 审计单元 1：CM 上下文、匹配恢复、Mixer/APM

日期：2026-11-07。生产参考 `a3b6c3dd3b69f0ac65b06482313de880a2322a4f`；P12 基线锁定提交 `475a031`，12 文件总上限 **41,814,147 B**。

> 本单元是独立的审计/Oracle 工作单元，不是真实调度的 Subagent。本环境没有 Subagent 调度接口。只修改诊断副本、探针和报告，`src/lib/` 与生产参考逐字节不变。本报告没有全文件压缩结果，没有改变线上格式或默认比特流。

## 1. 证据和复现边界

- **52 个独立进程、每个 262,144 B 原始输入**；每个进程只处理一个固定切片和一个变体。全部 encode/decode SHA-256 往返通过；最慢单次 **7,640 ms**。编码子进程有减去构建用时后的 17.5 s 总预算，超时 SIGKILL；不是长任务内仅检查 JS 时钟。
- 每个 payload 是冷启动 **raw v15 CM**，不是生产 chooser 的获胜方案，也不包含 UCZ 组目录/新版本标志。当前切片表宽与整文件大组不同。下述字节增减不能直接冒充完整 UCZ 收益。
- xml/nci/samba 使用 text，其余使用 bin。samba 的选址从真实 C 成员开始：前 219,702 B 是该成员，后续为紧邻 tar 数据；不是把全部 256 KiB 冒称纯 C。ooffice 是 PE x86 `.text`；Mozilla 是 **Alpha ECOFF `.text`，不是 x86**。
- 选址在实验前固定。`*-late` 是固定的第二位置，不按压缩率选择。输入偏移、来源 blob、原文件及切片 SHA：`scripts/diag/p12-results/slices.json`。
- 原始收据：`scripts/diag/p12-results/agent1/*.json`；汇总：该目录 `summary.json`。收据含实际生产源码 hash、诊断工具 hash/快照、变体源码 hash、时间、输出 hash 和 roundtrip。`tool-sources/` 保存不同阶段的工具文本，不把它们误称生产修改。
- 复现（项目目录；使用新的P12_RUN_TAG写入独立ignored目录，原收据不覆盖）：
  ```sh
  node scripts/diag/fetch-corpus.mjs xml nci samba mozilla ooffice osdb sao mr x-ray dickens webster reymont
  python3 scripts/diag/p12/prepare-slices.py  # 仅验证/复制数据，无全文件编码
  P12_RUN_TAG=replay-agent1 timeout --signal=KILL 19s node scripts/diag/p12/run.mjs agent1 mozilla-code gap-distance
  ```
  每条编码命令是单独实验，不运行旧 `probe-p8-*` 或完整 codec 测试。首次 attrib 构建的严格替换锚点发现有两处匹配，**构建失败且未编码**；收紧到行首后成功。未将那次失败计为 PASS。

## 2. H[0..8] 的真实输入

位置：`src/lib/coder.ts:708–742`。下表适用于 v13/v15，`bi=pos-i` 的历史字节；表索引还混入当前字节位前缀 `c0`，不是仅按这些字节索引。

|H|text|bin（geomStride=0）|
|---|---|---|
|0|0，即位前缀条件下零阶|同左|
|1|b1|b1|
|2|b1,b2|b1,b2|
|3|b1,b2,b3|b1,b2,b3|
|4|b1,b2,b3,b4|b1,b2,b3,b4|
|5|b1…b6|b1,b3（已有稀疏）|
|6|curWord,b1|b3,b4|
|7|prevWord,curWord 或 b1|b1,b4|
|8|b1,b3,b4|组合 b1,b2,pos&3，再配 b4,b5|

- `curWord` 是已有的 ASCII 字母、不区分大小写运行哈希；数字/下划线当前是边界。边界保存 `prevWord`。不能提“新增运行词哈希”作为发现。
- `wordTokens=true` 时 >=128 的字节独立推进词哈希，避免 WORD-PRE v1 的词元被当普通边界。v2 双字节词元是否真的以一个词建模，见审计单元4；本单元未把 raw-text 实验说成 WORD-PRE 测量。
- bin 的 `binCtx8=false`，H8 默认取 b5，b8 替换实验已有历史代码但未启用；**4 字节相位已在 H8 与 bin 辅 Mixer 中存在**。
- bin `geomStride>0` 是另一套九上下文：列相位 p、连续历史、上一/上两记录同列 a/a2、b1+a、b1 与上一记录前列差值等。本单元表格不把它混入普通 bin。

### 相关性不是删特征依据

在 **step() 取表后、learn() 前**采样；没有沿用旧 byte-level attribHook 的下一字节 hashes/上一字节 idx 错位方法。`attrib` 在四输入上与 base 的 payload SHA 完全相同。

## 4. mht4/mht8：已有确认；真正发现是默认关闭路径的距离错位

位置：`coder.ts:1095–1200`。

- v13/v15 text/bin 的 mht4 `minLen=4`，候选向后逐字节确认最多32字节，不是“哈希相同就信任”。mht8 只在短匹配 `<6` 查询、需距离>64，向后确认最多64，且 `l>=6` 并更长才替换。它允许8字节hash碰撞但实际已确认至少6字节，不是8字节强等价断言。
- 新增一次显式4字节预检（`confirm4`）在三个 bin 切片上 **字节差0且 payload SHA一致**。这是冗余确认，不是压缩改进。原mht4查到候选后拒绝率：xml 191/19,921，mozilla 3,577/52,047，ooffice 7,704/69,000，osdb 3,029/36,090。拒绝不是误采纳率，更不是误解码率。
- 将最短匹配提高至6，mozilla **+737 B/+0.965%**，ooffice **+806 B/+0.703%**，osdb **+551 B/+0.742%**。短匹配仍有净价值。
- `mlen` 成功逐字节增长，错字节归零；当前字节的预测位前缀不一致后即停止该 match 输入。Mixer match 输入来自 `msm[min(mlen,31)]` 的 stretch 和期望位符号。MSM 32档，更新右移5；主 Mixer 的匹配态分无/短(<16)/长。长于31继续增长但置信档已饱和。

### 距离错位的源码推导

`learn()` 已经执行 `pos++` 才进入 `byteUpdate(byte)`；此刻正在比较的历史目标是 `mptr`，当前实际字节坐标是 **pos−1**。恢复代码却保存 `lastDist=pos−mptr`，比真正的字节距离大1。该路径**默认关闭**，不是线上数据损坏。诊断变体：

1. `gap-on`：仅打开原恢复。
2. `gap-distance`：打开恢复，仅将保存距离改成 `pos−1−mptr`。
3. `gap2`：在2基础上要求刚过去的两字节都相同，而非一字节相同即设 mlen=2。

|---|---:|---:|---:|---:|
|mozilla-code|76,362|+36|**−1,068 / −1.399%**|−746|
|ooffice-code|114,639|+33|**−1,246 / −1.087%**|−878|
|osdb-mid|74,268|−142|**−186 / −0.250%**|−152|
|mozilla-code-late|74,239|未测|**−1,331 / −1.793%**|未测|

六次独立 raw-CM 实验的节约之和 **5,144 B = 5.144 kB**；这不是一次多文件编码，也不是41.8MB基线的实测减少量。三组第二位置同向，值得进入下一阶段；不能将它与BCJ/变换后的收益相加，因为它们可能解释同一冗余。

**风险与下一门：**一字节确认却设 mlen=2 是原有置信策略；两字节确认反而少赚，不能在没有机制证据时继续扫 mlen/等待窗口。raw文本、WORD-PRE词元、res不启用match的路径、大组/跨块状态及dual编码尚未覆盖；任何生产集成都会改变CM流，必须新版本显式区分、编解码及worker同步、完整容器严格更小才采纳。本轮不启用。

## 5. weights/weights2、stretch、a1/a2

位置：`coder.ts:48–65, 275–450, 625–698, 829–1020`。

- text/bin 九表加 match 和偏置256，共11个输入；表中16bit概率先降到12bit索引，经4096项STRETCH转logit。点积除65536进入整数squash；不得仅改某一侧浮点/舍入或STRETCH而沿用旧版本。
- 主weights为 **24组（8 bit×3匹配态）**，误差乘8；bin-only辅weights2分配64×8组，初值0，误差乘**2，即主学习率1/4，不是源码注释的“减半”**。bin辅上下文含pos&3、b1类别和match状态。text不启用辅Mixer。
- a1实际默认 `ctx=1`，c0的256桶；a2实际默认 `ctx=2`，前字节高2bit×3匹配态共**12桶**。两者rate5、weight1。不是旧注释中的a1默认768、a2默认2048。a2在raw text默认开、WORD-PRE text默认关；transpose/特定行残差另有对称抑制。
- learn() 对主辅使用最终APM后误差；将两者改用上游 `lastPr` 的机制对照：xml **+32 B/+0.248%**，osdb **+381/+0.513%**，ooffice **+56/+0.049%**，不支持更改。
- a1增加匹配态（256→768桶）：osdb **−201 B/−0.271%**，nci **+8/+0.058%**。不是零回退方向。osdb关闭辅Mixer **+431/+0.580%**，现有bin辅Mixer有边际价值。
- APM插值 `w` 用于预测；更新时两个端点各自同速向目标移动，并非源码注释所称严格“按插值权重SGD”。可作为将来数学审查问题，但**没有本轮净收益证据**，不据此随意改学习率或给出收益。

## 6. 审计判断

1. **进入候选列表：恢复距离错位修正 + 保守独立模式**。机制明确、两个位置同向；局部5.144kB，完整容器和全文件收益未知。
2. **不建议：**新增4字节确认（0收益）、普遍提高minLen、把bin改词模型、全局扩数字/下划线边界、重复叠加相位、从相关性直接删表。
3. **暂缓：**a1匹配态/梯度变更。前者跨文本回退，后者三个输入都回退；不新增启发式分支来掩盖。
4. 当前12文件基线仍严格是用户本地 **41,814,147 B**；本单元没有证明任意一个完整文件的零回退，也不承诺新的吞吐或RSS。并行短测的时间/RSS只作收据，不作性能对比。
