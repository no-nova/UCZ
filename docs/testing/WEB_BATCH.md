# 网页端多文件压缩与精确 B 显示

## 范围

只改 React 界面、文件队列、Worker 客户端及相关测试。继续调用原 `src/lib/compress.worker.ts`，每个任务独立 Worker；`src/lib/` 与 P13.1 `ed09309` 完全一致，UCZ 语义和 40,233,692 B 基线不变。没有引入 P14 审计中的实验内核。

一次多选 / 拖放 / 运行中追加文件；最多两文件并发，输入在获得执行名额后才读取。任务有独立 ID，同名文件不会覆盖。取消会中断 Worker 并结束等待 Promise，迟到消息不能覆盖取消状态或新的任务。文件读取本身使用 `File.arrayBuffer()`，取消读取中任务后即使读取完成也不会开始编码。

成功结果保留独立下载和详情；只有逐字节校验通过的完整容器计入合计。空文件、超限、读取失败、Worker 失败、校验失败与取消状态单独显示。取消全部不移除已完成结果；清除已结束结果释放对应数据引用。

“完整字节（B）”为默认显示模式，使用整数和千位分隔，不通过 KB/MB 反算。自动单位模式使用正确的二进制 KiB/MiB/GiB；批量表与对照图保留精确 B 的悬停提示。所选文件的原始 / 压缩大小、分区表、对照图和汇总使用同一显示选项。区域成本仍是原有按模型成本分摊的数据，不把它重新解释为精确最终 Group 目录。
